## 三、逐里程碑改动

### M3-T5.5：事实卡加固

核心方向是让模型直接读取代码算好的结论，不再做时间减法、比分比较或无依据推测。

主要变更：

- 本回合时间线原点收敛到“正式开打”，冻结购买阶段用负数表达。
- 比分从 CT/T 原始排列改为“我方阵营 + 我方比分:对方比分 + 领先/落后标签”。
- 回合阶段由代码按产品负责人定义计算：
  - 0–15 秒：开局
  - 15–30 秒：前期
  - 30–70 秒：中期
  - 70 秒起：后期
  - 下包后：T 为守包，CT 为反攻包点
- 护甲降噪为“有甲/无甲”，不再强调挨打时的护甲数字变化。
- 时间线补充并修正正式开打、弹匣状态、换弹、道具使用、拿包/丢包等事实表达。
- 撤回 M3-T5 的“事实 + 推测”两段输出，仅保留事实层，原因是推测层在缺少视觉信息时大量臆测敌人、地形、击杀者和队友。
- 强化脏字与点位事实检查，并修复黑名单误伤武器名的问题。
- 曾引入“密集时间段”代码标记，随后在 M3-T5.6 根据产品反馈删除。最终方案保留完整时间线，由提示词要求模型关注短时间连续变化，不在事实层判断“密集是否重要”。

### M3-T5.6：离线评测基础设施

这一阶段把“模型看起来说得不错”改成可重复、可评分的工程指标。

主要变更：

- `bench.py` 新增多录制流式分析模式，可一次评测多个真实录制。
- 初始协议为两行：
  - `事件：` 一句短事实
  - `场面：` 2–4 句事实说明
- 分别记录事件行到达时间和完整回答时间，便于区分可播报延迟与完整生成延迟。
- 新增严格人工评分数据结构：
  - 整句是否正确
  - 正确原子事实数 / 原子事实总数
  - 错误原因与备注
- 新增离线评分模式；对已有报告追加评分时不会读取 API key，也不会触发模型调用。
- 评分文件与报告 case ID 必须完全一致，禁止漏题、添题或重复 ID。
- 上游必须显式锁定，关闭 fallback，避免不同供应商造成延迟与输出波动。
- `llm.py` 新增流式 OpenRouter 解析、单次调用、事件/完整截止时间、部分事件文本和 usage/cost 记录。
- 删除事件卡“密集段”标记，恢复完整顺序时间线。
- 做了多个型号与服务商烟雾测试和对照报告；型号选择仍是评测候选，不是写入产品配置的最终选型。

### M3-T5.6.1：冻结产品 answer key

产品负责人逐题重写并确认 28 个事件短句目标，覆盖 5 份真实录制：Ancient、Anubis、Nuke 两段、Overpass。

answer key 不要求逐字相同，而是定义：

- `expected_summary`：产品认可的目标表达
- `required_facts`：整句必须覆盖的原子事实
- `forbidden_claims`：不能出现的编造或角色错误

典型事实包括：

- 前期/中期/后期以及守包、反攻包点
- 普通击杀、爆头、双杀、三杀
- 摸烟、赢下对枪、击杀后被补
- 带包阵亡、大残阵亡
- 回合胜负、灭队、炸弹引爆/拆除
- 未观测到正式开打时不猜阶段
- 回合结算时是否应保留个人贡献

同时新增 answer key SHA 绑定，保证评分永远对应同一份不可漂移的语义标准。

### M3-T5.6.2：达到 95% 准确率

产品阶段目标调整为“先保证答案正确”，事件短句上限暂时放宽到 30 个汉字，事件/完整截止时间均放宽到 10 秒。

代码侧新增确定性标签：

- 击杀条目标注本回合第几杀。
- 击杀瞬间若满血或不高于 30 血，标注“击杀时满血/剩 N 血”。
- 击杀与掉血间隔不超过 1 秒，标注“近同时掉血”，供模型概括为赢下对枪。
- 击杀发生在出烟后不超过 1 秒，标注“出烟后 N 秒”，供模型概括为摸烟击杀。
- 阵亡发生在最后击杀后配置阈值内，标注“击杀后很快阵亡”，供模型概括为被补枪。
- 死亡阶段与击杀阶段分开标注，避免用死亡时刻覆盖击杀阶段。

模型输出协议从两行改为三行：

1. `核对：` 结构化自检，列出事件类型、获胜方式、开打观测、武器、阶段、血量、杀数、阵亡、关系和个人重点。
2. `事件：` 最终短句，是当前准确率目标和未来可播报候选。
3. `场面：` 较长事实说明。

核对行只用于评测和约束生成，不会被宠物播报。事件延迟从请求开始计到完整 `事件：` 行结束，因此包含核对行耗时，是偏保守的真实延迟。

评测参数：

- 温度：0
- 完成上限：128 token
- 默认固定种子：42，可通过 `--seed` 修改
- 事件短句上限：30 个汉字
- 事件/完整截止时间：10 秒 / 10 秒
- 整句准确率通过线：95%
- 原子事实准确率通过线：95%

三种固定种子结果：

| Seed | 整句准确率 | 原子事实 | 请求 | 事件 P95 |
|---:|---:|---:|---:|---:|
| 42 | 27/28，96.4% | 95/96，99.0% | 28/28 | 1.721s |
| 43 | 27/28，96.4% | 95/96，99.0% | 28/28 | 1.670s |
| 44 | 28/28，100% | 96/96，100% | 28/28 | 1.728s |

三个种子的平均整句准确率为 97.6%。

### M3-T5.6.3：随机压力测试与泛化修复

在冻结 28 题之外，临时生成 12 个受约束卡级场景，随机化武器、地图、比分、血量与时序，覆盖：

- 满血普通击杀
- 残血爆头对枪
- 摸烟击杀
- 前期一杀 + 下包后双杀构成三杀
- 击杀后被补
- 零杀普通死亡
- 开局白给
- 双杀后大残阵亡
- 三杀贡献后阵亡并结算
- 早死后炸弹引爆，个人事件应省略
- 活到后期一杀并获胜
- 未观测开打时刻的普通死亡

首轮严格检查约为 10/12，暴露两个冻结集未覆盖的泛化缺口：

1. `【刚刚】白给` 被“零杀普通死亡”规则覆盖，输出成普通死亡。
2. 分阶段三杀中的“反攻包点双杀”被输出成“再杀两枪”，说明模型仍在自行数击杀。

修复方式：

- 提示词新增白给独立分支；事件类型为白给时必须保留“白给”，不得降级成普通死亡。
- `event_card.py` 预先按阶段/职责累计击杀数，在该阶段最后一次击杀上直接标注“该阶段双杀/三杀/四杀/五杀”。
- 模型不再承担阶段内击杀计数。

修复后相同随机种子与模型种子下为 12/12，事件 P95 1.548 秒。

真实 28 题再次回归：

- 整句：27/28，96.4%
- 原子事实：95/96，99.0%
- 请求：28/28 成功
- 事件 P95：1.448 秒
- 唯一错误：某条回合胜利正确核对出 M4A1-S，但最终事件短句压缩时遗漏武器；回合结果、三杀、阵亡与显著贡献均正确。

## 四、当前模块职责与数据流

当前离线事实评测链路：

```text
真实 GSI JSONL
  → gsi.parse_snapshot
  → session / events / situation
  → event_card.render_event_card
  → reading.md + inference.md
  → llm.OpenRouterClient.analyze_stream（一次调用，无重试）
  → 核对 / 事件 / 场面
  → bench Markdown 报告
  → 冻结 answer key + 人工评分 JSON
```

职责没有跨层：

- `events.py`：仍只检测离散事实；没有加入模型逻辑或提示词规则。
- `situation.py`：累计时间线，并记录击杀瞬间的确定性低血/满血事实。
- `event_card.py`：渲染代码已判定的阶段、关系和阶段杀数，不访问网络。
- `reading.md`：解释代码标签与 CS 术语。
- `inference.md`：定义评测输出格式、事实取舍和禁止编造规则。
- `llm.py`：业务无关的 OpenRouter 调用与流式解析，不知道 CS2 事件语义。
- `bench.py`：只做离线回放、调用、延迟统计和人工评分，不被线上链路引用。

## 八、已知限制与未完成项

1. **没有真正的新 held-out 实战事件。** 当前唯一未进入冻结集的非空录制只有 12 张快照、0 个检测事件，无法用于泛化评估。需要再录一局在线休闲作为真正的盲测集。
2. **随机 12 题是卡级受约束合成，不是正式 M3-T6 数据集。** 临时生成器未提交；它使用现有内部事实字段与代码标签，但没有从真实 raw payload 模板逐字段改造。正式 M3-T6 仍需遵守数据清单白名单，产出可永久回归的 GSI JSONL。
3. **当前 95% 只指事件短句。** `场面：` 行未纳入冻结 answer key 的整句准确率目标，且 128 token 上限下个别场面行会被截断。未来若场面描述进入产品，需要单独冻结标准和评分。
4. **30 字与 10 秒是 T5.6.2 的准确率阶段放宽值。** AGENTS.md 中原产品目标仍是模板长度 P90 19 字；线上接入前需要决定回到 19 字，还是以实测语音时长重新定上限。
5. **三行自检会增加输入输出 token 和首句延迟。** 当前事件 P95 仍低于 2 秒，但线上是否保留完整核对行应由 M3-T10 的成本/延迟实验决定。
6. **仍有 1/28 的压缩遗漏。** 最新真实回归中模型在核对行看到了武器，但事件行漏写武器，说明“核对正确”不能保证最终短句完全覆盖。
7. **当前模型不是架构层写死的正式选型。** `qwen/qwen3.5-122b-a10b` + `alibaba` 是目前稳定的评测组合；最终服务商、价格与线上 SLA 仍需在正式横向选型中确认。
