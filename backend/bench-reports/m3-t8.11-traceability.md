# M3-T8.11 事件卡生成链路追溯审计

审计日期：2026-08-13

代码基线：M3-T8.10 之后、M3-T8.11 本次修复

数据范围：`backend/recordings/` 下 7 份非空真实录制、`backend/scenarios/` 下 35 份合成场景；共检查 114 张策略入选卡。

## 结论摘要

- 确认 7 类事实缺陷并已修复：AWP 击杀武器归因错误；闪光/烟雾/燃烧在缺失帧处被拆成两段；观测中断被当作正常出烟；换弹观测缺失被写成“未完成”；道具库存跨缺失帧继续比较；死亡时缺失的 `round_kills` 被补成 0；待确认 AWP 空枪把缺失杀数当作 0。
- 另修复 2 个直发格式缺口：完整卡与实际模型输入在报告中未区分；仅发【刚刚】后，单次大狙空枪原本只在历史区、会从模型输入消失。
- 1 项保留为“有嫌疑但未复现”：`primary_weapon` 是“本回合首次在库存看见某主武器”，不是严格的 active 手持切换。真实数据 195 次首次看见主武器中有 43 次当帧并非 active，但 114 张入选卡没有复现错误的“换枪后立刻杀”。本轮不擅自改判据。
- 修复后自动语义检查为 0 条矛盾。

## 语义一致性检查

自动检查了 7 份非空真实录制和 35 个合成场景的 114 张策略入选卡，检查粒度为“焦点连续段中的单个动作”，避免把历史中的对枪胜利与后续残血击杀误报为同一动作。

检查组合：

- 同一动作：`对枪胜利` + `残血击杀`；
- 同一死亡动作：`一枪没开就没了` + `对枪输了`；
- 同一死亡动作：`一枪没开就没了` + `打空了还是没打过`；
- death 之后出现 kill；
- smoke/flash/burn 的 end 早于 start 或无 start；
- `round_live` 之后仍出现负秒；
- 同一时刻同一种效果同时 start/end。

结果：**0 条矛盾**。

一次初版全卡字符串扫描曾报出 `gsi-20260810-114649-321103.jsonl:event-00000003` 同时含“对枪胜利/残血击杀”。回看代码和 payload 后确认：前者属于 21.3 秒的第一杀，后者属于 28.5 秒的第二杀，不是同一次动作。检查器因此改为按【刚刚】动作片段判定；没有为消除误报而改业务事实。

## 新的直发格式

模型输入固定为：一行极简抬头 + 自然中文的【刚刚】。完整卡仍由 `render_event_card()` 生成并写入评测报告；模型只接收 `render_model_event_card()`。

格式：

```text
de_nuke CT 5:3 领先
【刚刚】
焦点：普通死亡
场景标签：对枪输了
阶段：中期；回合时刻：42.3秒；连续事件跨度：0.6秒
经过：玩家开火，随后掉了35血；同一快照还观察到阵亡
```

设计理由：

1. 焦点前置，模型不必从句尾括号寻找中心；
2. 场景标签单列，完整保留 22 个语料索引键；
3. “随后”只表达可确认先后，“同一快照还观察到”明确禁止编造顺序和因果；
4. 精确秒数、阶段、连续跨度仍保留，没有从旧【刚刚】丢事实；
5. 抬头只放地图、阵营、我方在前比分、代码算好的局势、非零连败，不加入全场 K/A/D/MVP。
