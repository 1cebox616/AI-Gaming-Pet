# M3-T10.5 托盘模型状态显示

## 实现

沿既有 `state → frontend/backend-bridge.ts → update_pet_menu_state → Rust PetMenu`
路径增加两项只读菜单文本，位于游戏状态行正下方：

```
当前：AI 模式
本次花费：$0.0123
```

后端的 `llm.reason` 已经可区分以下模板模式，前端只负责映射显示：

| 后端状态 | 托盘显示 |
|---|---|
| `mode=ai` | 当前：AI 模式 |
| `reason=未启用` | 当前：模板模式（未启用） |
| `reason=型号未配置` / `环境变量缺失` | 当前：模板模式（未配置） |
| `reason=连续失败` | 当前：模板模式（连续失败） |

后端字段无需补充。旧后端缺少 `llm` 字段时，前端按「模板模式（未启用）」处理；
后端断开时两行均显示 `—`，避免保留旧值。花费为 `null` 时显示「本次花费：未提供」，
不按 token 估算。

## 自动验证

- 前端 `llm-status.test.ts` 覆盖有效 AI 状态、字段缺失和连续失败状态。
- Rust 单元测试覆盖扩展后的菜单状态携带模式与花费文本。
- 后端：`359 passed, 4 deselected`；4 项为本机缺少 OneCore 中文语音。
- 前端：`npm.cmd run test`、`npm.cmd run build`、`npm.cmd run format:check` 均通过。
- Rust：`cargo fmt --check`、`cargo test`（4 项）均通过。

## 需人工验证

1. 两行是否实际出现在 Windows 托盘菜单、且位于游戏状态行下方。
2. AI、未启用、未配置、连续失败四种文字是否正确切换。
3. 上游返回花费时，数字是否随每次模型调用累计；未返回时是否显示「未提供」。
4. 关闭后端后，两行是否立即显示 `—`，而不是遗留旧状态。

## 产品负责人确认步骤

1. 启动程序并右键系统托盘宠物图标，确认游戏状态下方有「当前」与「本次花费」两行。
2. 保持 `[llm] enabled = false` 重启后端，确认「模板模式（未启用）」。
3. 将 `enabled = true` 且将 `model` 留空，重启后端，确认「模板模式（未配置）」。
4. 填写有效模型后再设置同一 PowerShell 的 `OPENROUTER_API_KEY`，开始一局游戏；
   有一次通过闸门的模型调用后，确认「AI 模式」和花费显示。
5. 要验证连续失败，可临时将 `model` 改成错误型号并重启；连续三次事件调用失败后，
   应显示「模板模式（连续失败）」。验证后恢复正确配置。
