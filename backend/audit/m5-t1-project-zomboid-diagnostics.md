# M5-T1 Project Zomboid 捕获兼容性诊断记录

统计日期：2026-08-23

本文件收录 Project Zomboid 的兼容性诊断会话。这些会话存在已确认的捕获端可见光标异常，或专门用于定位该异常，因此全部不计入《M5-T1 画面变化探针实测汇总》的正式算法测试数据。

## 当前结论与技术债输入

- 在 Project Zomboid 中，只要当前 Windows Graphics Capture（WGC）会话存续，游戏内可见鼠标光标就会消失；探针退出、捕获会话释放后，光标立即恢复。该时间关系已重复观察。
- 将 WGC 的 `is_cursor_capture_enabled` 从 `false` 改为 `true` 后，游戏内光标仍不可见，保存的截图中也没有光标。因此“未请求合成光标”不是充分根因。
- 从独占全屏切换到无边框窗口没有消除现象；移除旧的阻塞式取帧路径也没有消除现象。
- 当前证据只能把问题收敛到“Project Zomboid 与当前 WGC/zbl 捕获会话的交互边界”，不能继续断言是 Windows API、zbl Python 绑定或游戏自身中的哪一方缺陷，也不能泛化到其他游戏。
- 建议架构师记入技术债：在视觉捕获接入产品常驻服务或冻结后端选型前，至少用另一款依赖游戏内鼠标光标的游戏做同参数 A/B。若跨游戏复现，再评估另一种 WGC 绑定或下一顺位后端；若只在 Project Zomboid 复现，则作为已知单游戏兼容性问题处理，不为该游戏先写特判。
- `--capture-cursor` 仅作为复现实验开关保留，默认仍为关闭，不改变既有捕获行为。

### 诊断 PZ-1 采样空洞与静止段边界

正常轮询间隔的中位数为 2.001 秒，但 61 个相邻轮询中有 9 个间隔超过 3 秒：
10.393、7.770、12.035、11.546、28.705、4.279、9.587、49.438 和 91.516 秒。
探针记录的单次截屏最大耗时为 89.537 秒，与最长轮询间隔相符；因此这不是单纯
PNG 未达到阈值，而是对应时间段没有取得可比较的新帧。异常主要发生在教程步骤、
黑屏过渡和新游戏创建/载入附近。约 317 秒会话只完成 62 次轮询，产品负责人描述的
两段行走和部分界面翻阅很可能落在这些采样空洞内，现有数据不能判断它们本应触发
却未落盘，还是根本没有成为探针输入。

第 40 帧之后的第 41–62 帧持续约 42 秒，瞬时平均振幅仅为 0.000077–0.000110，
没有主动落盘。这说明截图内容保持稳定，但第 40 帧明确显示“游戏暂停”且状态面板
仍展开；没有后续 PNG 能证明这段已经关闭菜单并回到正常运行的游戏世界。因此不能
把它当成 2D 游戏运行状态下的静止环境基线，也不能用来判断植被、角色待机或其他
环境动画是否会误触发。

结论仅限本段：默认策略稳定捕获了大面积菜单、背包/容器、教程提示、黑屏过渡和
新游戏场景选择，局部教程文字提示也在第 32 帧以 0.021570 刚好触发，和用户提供的
操作上下文部分吻合。另一方面，新游戏载入前后出现 49–92 秒级的抓帧阻塞，使两段
行走和菜单操作缺少连续证据；这是本次比指标阈值更直接的问题。唯一的新游戏实机
PNG 是一张暂停且打开状态面板的强制帧，故本段尚不能回答正常游玩时“会 capture
哪些移动变化”，也不能回答静止运行时是否保持安静。后续若复测，应把“已完全进入
游戏后的正常行走”和“加载/创建流程”分成两个会话，并在静止段关闭所有暂停菜单。

### 诊断 PZ-2 菜单动画、移动采样空洞与鼠标异常

主菜单的第 8–30 帧共 23 次轮询，其中 11 次仅因循环背景动画主动落盘，占
47.8%；规则选择界面的第 35、38 帧也在选项未变时被大幅预览动画触发。该结果
说明默认整屏平均振幅不能把“菜单背景动画”与有意义的用户操作分开，但不据此
评价其他候选指标或选择策略。

轮询间隔中位数为 2.001 秒，但有 5 个间隔超过 3 秒：8.178、12.205、7.198、
5.888 和 51.003 秒。第 41 帧进入载入画面后，第 42–59 帧的瞬时平均振幅最大仅
0.000479，未触发落盘；第 60 帧才出现实际游戏画面。第 60 帧后的 3 次轮询保持
在状态面板画面，随后 `grab()` 阻塞约 49.028 秒，直到第 64 帧退出确认框才返回。
因此产品负责人进行人物移动的主要时段没有任何输入帧进入六指标计算。第 60 与
64 帧的位置变化只能证明移动发生过，不能说明默认指标捕获了移动，也不能把缺少
PNG 解释为移动低于阈值。本结果再次复现诊断 PZ-1 的 Project Zomboid 实机抓帧阻塞，
且这次把问题定位到游戏载入后的实际移动阶段。

鼠标光标异常的代码层排查：`capture.py` 没有调用 `SetForegroundWindow`、
`SetFocus`、`SetCursor`、`ShowCursor`、`ClipCursor` 或任何输入注入接口；使用
`--title` 时只枚举可见窗口并读取句柄、标题和进程名。唯一的光标相关参数是创建
WGC 会话时传入 `is_cursor_capture_enabled=False`，当前 19 张 PNG 也确实都不含
鼠标指针。Microsoft 对 `GraphicsCaptureSession.IsCursorCaptureEnabled` 的定义
仅是“是否把光标包含在捕获内容中”，没有说明会改变源窗口中玩家看到的光标；
因此它可以解释“截图里没有光标”，不能直接解释“游戏画面上的光标消失”。当前
使用的 `zbl 0.7.1` 项目也明确说明仍处早期开发、只验证 happy path。最稳妥的记录
是：Project Zomboid 与当前 WGC 绑定之间存在尚未定位的兼容性异常，表现为实机阶段
长时间不交付新帧，并伴随一次用户可见的游戏内光标消失；两者是否同因尚不能确认。
后续应做短时 A/B：仅切换 WGC 的光标合成开关，分别观察玩家屏幕光标与帧交付，
再测试关闭捕获边框或下一顺位后端；本任务不修改截屏后端，也不把假设写成诊断。
