## 二、实测得到的关键事实

- 单一平均振幅不能兼顾两类场景：全屏低幅环境动效可能持续抬高平均值，局部文字
  或小面积 UI 变化又可能被大面积静止背景稀释。因此保留多指标数据，尚未拍板策略。
- 2 秒轮询会天然漏掉完整发生在两个采样点之间的短动作；夜视仪/手电筒快速开关
  已出现此类证据，间隔仍待后续结合资源占用决定。
- 暗场不是统一的“不可检测”：整屏转向仍可产生高差异，但近乎全黑的慢速移动可
  长时间低于默认平均振幅阈值。
- 水面海浪与主菜单循环动画可在玩家没有操作时持续触发，说明“画面变化”不等于
  “值得让宠物发言”；语义筛选属于后续视觉理解层，不能靠本任务阈值冒充。
- Slay the Spire 2 的两场战斗分别有 95.5% 与 95.0% 的成功轮询落盘；3 分 25 秒
  产生 67 张、175.40 MiB。动画密集的高分辨率 2D 游戏会快速接近循环容量上限，
  且默认变化指标无法区分关键局势与普通卡牌/回合动画。

## 三、本次通用取帧修正

- 把阻塞式 `zbl.grab()` 改为非阻塞 `try_grab()`；WGC 暂无新帧时立即返回，探针
  继续按间隔运行，Ctrl+C、CSV 和最长静默计时不再被一次 native 等待锁死。
- 每轮排空 `zbl` 的有界 FIFO，只把最新可用源帧交给检测器，避免低频消费者逐张
  回放积压旧帧；热源最多取 64 帧，保证循环有硬上限。
- CSV 新增“是否取得画面、本次取出源帧数、本次抓帧耗时毫秒、截屏状态”；无帧
  行的六指标留空，不写死为零。退出汇总新增成功抓帧、无新帧、源帧取出统计。
- 新增合成会话测试：队列只返回最新帧、无帧立即返回、热源排空有硬上限、无帧行
  即时 flush。没有增加依赖，没有游戏名判断，没有改变变化算法和落盘阈值。

### 技术债：Project Zomboid 与 WGC 捕获会话的光标兼容性

- Project Zomboid 的 4 次诊断会话均不计入正式测试数据。前两次暴露阻塞取帧和旧帧
  积压；后两次分别验证非阻塞修正和 WGC 光标合成开关。完整数据与现场观察见独立
  诊断文件。
- 已确认的现象是：该游戏中当前 WGC 会话存续时，游戏内可见鼠标光标消失；探针
  退出、会话释放后光标立即恢复。该现象在全屏与无边框窗口均出现。
- `is_cursor_capture_enabled=false/true` A/B 结果相同，截图也都不含光标；移除阻塞式
  `grab()` 后仍复现。因此光标合成开关、旧阻塞路径和显示模式都不是充分根因。
- 现有证据只能把责任边界收敛到 Project Zomboid 与当前 WGC/zbl 捕获会话的交互，
  不能判定是 Windows API、zbl 绑定还是游戏自身，也不能泛化到其他游戏。
- Slay the Spire 2 已提供第一组跨游戏负对照：同样使用
  `is_cursor_capture_enabled=false` 连续捕获 3 分 25 秒，游戏内光标一直正常可见。
  因此该异常不是当前 WGC 会话在所有鼠标驱动游戏中的普遍行为。
- 技术债仍保留为 Project Zomboid 单游戏兼容性问题，不先写游戏特判。只有其他游戏
  再次复现时，才升级评估另一种 WGC 绑定或下一顺位后端。
- 新增 `--capture-cursor` 诊断参数并写入 `session.json`，默认关闭，不改变既有行为。

### Project Zomboid 诊断结果摘要

- 诊断 PZ-3 仍不计入正式玩法数据：130 次轮询中成功 81 次、无新帧 49 次；
  最长连续 41 次无新帧期间探针保持 2 秒轮询，证明应用层无限等待已经消除。

- 诊断 PZ-4 开启 WGC 光标合成后仍不可见；探针停止后光标立即恢复。A/B 已完成，
  结论和后续边界按上方技术债处理，不把单游戏现象写成通用根因。
