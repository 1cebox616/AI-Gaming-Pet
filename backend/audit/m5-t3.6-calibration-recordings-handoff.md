## 二、会话 A：灰区战争多段静止与状态切换

本地目录：`backend/recordings/capture/20260825-200156/`

本地详细标注：`backend/recordings/capture/20260825-200156/context.md`

### 产品负责人现场记录

这不是一段被输入“污染”的待机录像，而是有意设计的多条件序列：

1. 同一个视角切换手电筒状态，并在切换前后分别保持静止。
2. 下蹲、看向地面后保持静止。
3. 移动到另一个位置后保持静止。
4. 最后保持静止时，画面中有直升机起降和队友路过。

切换和移动段应保留：它们为互相关校准提供“输入先发生、画面后响应”的真值。静止段用于比较不同视角、姿态、位置和世界动态下的噪声地板。

### 机械分段

以下边界由 `input.csv` 的单调秒按输入事件簇机械切出；语义来自现场记录。边界是近似值，不是逐帧人工判定。

| 相对时间 | 机械状态 | 现场语义 |
|---|---|---|
| 0.0–83.9 秒 | 无键鼠事件 | 同视角第一段静止；手电筒切换前状态 |
| 83.9–90.2 秒 | 输入活动 | 手电筒切换候选段 |
| 90.2–180.1 秒 | 无键鼠事件 | 同视角第二段静止；手电筒切换后状态 |
| 180.1–188.6 秒 | 输入活动 | 下蹲/转向地面的候选过渡段 |
| 188.6–205.9 秒 | 无键鼠事件 | 看向地面的静止候选段 |
| 205.9–206.0 秒 | 短输入活动 | 姿态微调边界 |
| 206.0–254.0 秒 | 无键鼠事件 | 看向地面的第二段静止候选区间 |
| 254.0–263.3 秒 | 输入活动 | 移动到另一位置的候选过渡段 |
| 263.3–340.0 秒 | 无键鼠事件 | 新位置静止候选段 |
| 340.0–371.6 秒 | 零星输入及后续活动 | 进入最终观察位置的候选过渡段 |
| 371.6–520.8 秒 | 无键鼠事件 | 最终静止段；含直升机起降和队友路过 |

其中最后一段连续 149.2 秒无玩家输入，但存在明确的世界动态，适合验证“玩家静止不等于画面静止”。

### 对下一步的价值

- 互相关校准的三段主要阶跃候选：手电筒切换、下蹲/视角变化、位置移动。
- 同一游戏内有多种静止基线，可检查参数是否只对某一视角有效。
- 当前 `--calibrate` 以整个会话为单位；下一任务如需分别统计上述片段，应增加只读时间范围输入或等价的区间清单，不得复制或改写 raw/input 原文件。

## 五、三段数据合起来回答什么

| 问题 | 应使用的录像 |
|---|---|
| 灰区夜间暴雨的稳定环境噪声能否被压住？ | 会话 B 的 `[0.0, 147.7)` |
| 玩家静止但世界对象活动时是否仍能捕获变化？ | 会话 A 的 `371.6–520.8` 秒及其他静止片段 |
| 相同“零输入”条件跨游戏是否表现一致？ | 会话 B 与会话 C 对照 |
| 输入到画面响应大约滞后多少？ | 会话 A 的多个切换/移动阶跃；B/C 只能作零输入负对照 |
| 参数会不会只对单一视角或位置有效？ | 会话 A 的多个静止片段 |

最关键的机器事实是：两个纯静止样本在当前默认参数下差异很大——灰区战争纯静止段为 0 次主动触发，而燕云十六声纯静止整段有 65 次主动触发。下一步不能只优化单个游戏的上传率，仍应遵循“漏帧优先、上传率次之”，同时单列跨游戏静止上传率。

## 六、给下一任务的输入建议

1. 第二轮网格至少把会话 B 的纯静止区间和会话 C 全段作为两个独立 idle 角色，不做平均后再输入。
2. 会话 A 按上述区间分别统计静止段与输入活动段；整段总上传率只作完整会话参考。
3. 互相关先在会话 A 的多个明确阶跃上分别求滞后，再报告中位与离散程度；不要把所有输入混成一个相关峰后直接写死全局常数。
4. 使用 B/C 的零输入区间验证互相关实现不会凭空产生“输入导致画面变化”的匹配。
5. 所有区间边界都保留“机械近似”标记；需要精确事件帧时，应人工查看相邻 raw 帧，不得把产品负责人提供的语义自动扩展为未观察事实。
