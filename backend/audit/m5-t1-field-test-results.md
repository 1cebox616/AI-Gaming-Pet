# M5-T1 画面变化探针实测汇总

本文件集中记录产品负责人在真实游戏中的采样场景与客观结果，供架构师统一审阅。
当前阶段只积累样本，不据单次结果判断指标或策略“好不好”。原始 CSV、会话信息与
截图位于本机 `backend/recordings/capture/<启动时间>/`，该目录被 Git 忽略。

## 离线逐帧分析口径

- 每次录制结束后，先读取 `metrics.csv`，再逐张复核该会话实际落盘的 PNG，最后
  将分析追加到本文件。后续样本默认执行同一流程。
- “首帧”只是会话基准；“指标触发”表示所选策略在该次轮询超过阈值；“强制兜底”
  表示达到 `--max-silence` 后保存，不能视为检测器识别了当时画面内容。
- 指标比较对象是上一次轮询帧，但未落盘帧没有 PNG。因此，当主动帧的前一轮没有
  保存时，只能说明该帧可见什么，不能仅凭落盘图确定是哪一个局部变化触发；连续
  落盘帧则可直接比较相邻画面。
- 下表的画面内容与场景符合程度均为 coding agent 对落盘 PNG 的离线视觉复核，
  不是探针自动生成的语义结果，也不代表产品已具备图像理解能力。只描述与场景
  有关的非身份信息；不把画面中的真实玩家身份写入仓库。
- “符合”只表示保存画面与产品负责人提供的上下文一致，不代表当前指标或策略
  已被判定为好或坏。

## 本机采样频率性能对照

测量环境为灰区战争 `GZW` 窗口，原始帧 2560x1440，本机 16 个逻辑处理器。
每档读取同一 Python 探针进程约 20 秒的 Windows 进程计数器。CPU 同时列出
“占一个逻辑核的比例”和“折算整机 16 线程的比例”；工作集是当时驻留在物理
内存中的页面，私有提交量不等同于实际物理内存。单次短测只用于本机量级对比，
不作为长期内存稳定性结论。

| 轮询间隔 | 单逻辑核 CPU | 整机 CPU（16 线程） | 工作集中位/最大 | 私有提交中位/最大 |
|---:|---:|---:|---:|---:|
| 2.0 秒 | 2.145% | 0.134% | 100.60 / 104.09 MB | 586.93 / 590.46 MB |
| 1.0 秒 | 3.291% | 0.206% | 100.71 / 124.59 MB | 586.54 / 614.73 MB |

- 从 2.0 秒提高到 1.0 秒，实测单核 CPU 由 2.145% 增至 3.291%，本轮增幅约
  53.4%，没有出现严格翻倍。
- 1.0 秒档的 49 次采样中，截屏耗时中位 24.3 ms，六指标计算耗时中位
  6.6 ms；合计约 30.9 ms，占 1 秒周期约 3.1%。
- 两档工作集中位数几乎相同；1.0 秒档短测出现较高的工作集与私有提交峰值，
  仅凭本次 20 秒窗口不能判定为持续增长或泄漏。
